Week 4: Message Passing and Monte Carlo

Week 4: Message Passing and Monte Carlo

Overview. Week 3 ended with variable elimination: to compute a conditional p(x_F\mid x_E) in a graphical model, sum out the remaining variables x_R one at a time, pushing each sum inward past every factor that does not mention it. This lecture takes that algorithm in two directions. The first half starts from a model where exact inference is out of reach, the TrueSkill model for ranking game players, and then shows that on a tree variable elimination can be rewritten as messages passed between neighbouring nodes. Two sweeps of messages give every node’s marginal at once (belief propagation). Running the same updates on a graph with cycles gives loopy belief propagation, an approximation with few guarantees that is still useful in practice; the tutorial uses it to denoise a binary image. The second half changes strategy entirely: instead of summing over a distribution, we draw random samples from it. We cover ancestral sampling, simple Monte Carlo estimation of expectations, and two tools for distributions we can only evaluate up to a constant: importance sampling and rejection sampling.

Latent variables and the TrueSkill model

Some variables in a model are never observed, yet the model depends on them. What do we do with such a variable?

Definition. A latent variable is an unobserved variable that governs some property of the observed data in a probabilistic model.

If an inference question never asks about a latent variable z, we can simply marginalize it out (integrate over it, or sum if it is discrete), exactly as Week 3 summed out the remaining variables x_R (Exact inference as a conditional distribution in Week 3). In other problems the latent variables are the very thing we want to learn about. Clustering is one example, and the course returns to latent variables when it covers Gaussian mixtures.

The lecture’s running example of the second kind is TrueSkill, a ranking system for players of competitive games. The goal is to infer each player’s skill from observing who beats whom.

Definition. In the course’s TrueSkill model (a logistic simplification: Microsoft’s original TrueSkill adds Gaussian performance noise, giving a cumulative-normal win probability), each of N players has a fixed skill z_i \in \mathbb{R}. Before seeing any games, the skills are independent, each with its own prior p(z_i) (for example an independent Gaussian). Skills are never observed, so they are latent variables. In each game, the probability that player i beats player j is p(i \text{ beats } j \mid z_i, z_j) = \sigma(z_i - z_j), \qquad \sigma(y) = \frac{1}{1+\exp(-y)}.

The function \sigma here is the standard logistic function: it maps any real number into (0,1), equals \tfrac12 at 0, and approaches 1 as its argument grows. So two players of equal skill each win half the time, and the larger the skill gap z_i - z_j, the more likely the stronger player wins. Week 3’s restricted Boltzmann machine section (Restricted Boltzmann machines in Week 3) used the same letter for \sigma(y) = 1/(1+e^{-2y}), which has an extra factor of 2 because those units took values in \{-1,+1\}. In this chapter \sigma always means the standard version, 1/(1+e^{-y}).

Treating the games as independent given the skills, the joint distribution of all skills and all T game outcomes is the prior times one factor per game:

p(z_1,\dots,z_N,\text{game } 1,\dots,\text{game } T) = \Big[\prod_{i=1}^N p(z_i)\Big]\Big[\prod_{\text{games}} p(i \text{ beats } j\mid z_i,z_j)\Big].

Why the posterior is hard. Once we observe some games, the skills are no longer independent, even for two players who have never played each other. This is Week 2’s explaining-away structure (Conditional independence: three canonical structures in Week 2): a game outcome is a common child of the two players’ skills, so observing it couples them. If A beat B, then learning that B is strong makes it more likely that A is strong too. A chain of games (A played B, B played C) then couples A and C through B. As a result, even the exact posterior over just two players requires integrating over every other player’s skill:

p(z_1,z_2\mid\text{games}) = \int\!\cdots\!\int p(z_1,z_2,z_3,\dots,z_N\mid\text{games})\,dz_3\cdots dz_N.

This is an (N-2)-dimensional integral with no closed form. The rest of the first half builds a tool, message passing, that computes approximate posteriors of this kind.

TipQuestion: How do the TrueSkill variables and equations fit together?

The variables, restated.

  • N is the number of players and T is the number of games observed.
  • z_i \in \mathbb{R} is player i’s skill: one real number, fixed but unknown. It is the latent variable. A larger z_i means a stronger player.
  • p(z_i) is the prior over that skill, held before any game is seen. Assuming a Gaussian prior means we describe that belief with the normal distribution, here with mean 0 and variance 1: p(z_i) = \frac{1}{\sqrt{2\pi}}e^{-z_i^2/2}. This is a modelling choice, not a fact about the players. It says that before any games we expect skills to be centred at 0, with most players close to it and extreme skills rare. For example, the prior density at a skill of 2 is about e^{-2}\approx 0.14 times its density at 0. The posterior then combines this belief with the game results, so a different prior would give different skill estimates from the same games. The teaching example below makes this choice for each player.
  • “i beats j” is the observed result of one game. It is data, so we condition on it rather than infer it. To condition on a result means to treat it as a known fact and ask what it tells us about the unknown skills, rather than treating the result itself as something to estimate.
  • \sigma is the logistic function. It turns a gap in skill into a probability.

The equations, in parts.

1. The win probability p(i \text{ beats } j \mid z_i, z_j) = \sigma(z_i - z_j) takes three steps:

  1. Form the gap d = z_i - z_j. Only this difference enters the formula, so adding the same amount to both skills changes nothing.
  2. Compute e^{-d}. It is large when d is very negative and small when d is very positive.
  3. Compute \sigma(d) = 1/(1+e^{-d}). Three cases to read it by:
    • d = 0 (equal skill): \sigma(d) = \tfrac12, a coin flip.
    • d large and positive (i much stronger): \sigma(d) is close to 1.
    • d large and negative (i much weaker): \sigma(d) is close to 0.

The loser’s probability is the complement, p(j \text{ beats } i \mid z_i, z_j) = \sigma(z_j - z_i) = 1 - \sigma(z_i - z_j), because one of the two players must win.

2. The joint distribution. The product \Big[\prod_{i=1}^N p(z_i)\Big]\Big[\prod_{\text{games}} p(i \text{ beats } j \mid z_i, z_j)\Big] has two brackets, and each bracket is a kind of evidence:

  • The first bracket is the prior, one factor per player. It says which skill levels were plausible before any game.
  • The second bracket is the likelihood, one factor per game. It rewards skill settings under which the observed winner really did win.

Multiplying the two brackets gives the joint of skills and results. Conditioning on the results, which is what the posterior does, divides this by a constant, so the joint is the object the rest of the chapter works with.

3. The posterior integral. In p(z_1,z_2\mid\text{games}) = \int\cdots\int p(z_1,\dots,z_N\mid\text{games})\,dz_3\cdots dz_N the left side asks about two players only. The integrand is the full posterior over all N skills, and the integral averages away every other player’s skill. There are N-2 integrations, one per player we do not ask about. Each one couples to the others through the game factors, so none of them can be done on its own.

Teaching example. Take three players, A, B, and C, with invented skills. We will not infer anything here. We only evaluate the joint at one setting of the skills. Use the standard Gaussian prior p(z) = \frac{1}{\sqrt{2\pi}}e^{-z^2/2} for each player, and suppose two games were played: A beat B, and B beat C.

Set z_A = 1, z_B = 0, z_C = -1.

  • Prior factors. p(1) \approx 0.2420, p(0) \approx 0.3989, p(-1) \approx 0.2420. Their product is 0.02336.
  • Likelihood factors. For “A beat B” the gap is 1 - 0 = 1, so the factor is \sigma(1) = 1/(1+e^{-1}) \approx 0.7311. For “B beat C” the gap is 0 - (-1) = 1, so the factor is again \approx 0.7311. Their product is 0.5344.
  • Joint. Multiply the two brackets: 0.02336 \times 0.5344 \approx 0.01248.

Now shift every skill up by 1: z_A = 2, z_B = 1, z_C = 0. Every gap is unchanged, so the likelihood is still 0.5344. The prior factors change to p(2) \approx 0.05399, p(1) \approx 0.2420, p(0) \approx 0.3989, with product 0.005212. The joint becomes 0.005212 \times 0.5344 \approx 0.002785, a little under a quarter of the first value.

The takeaway: the games see only differences between skills, so they cannot say whether the whole group is strong or weak. The prior sees absolute levels, and it is the prior that makes the second setting less plausible. Each part of the joint has a job: the sigmoid reads gaps, the game factors multiply in one term per result, and the prior anchors the overall level.

Trees and elimination order

Week 3 showed that variable elimination’s cost depends on the graph structure and on the elimination ordering, and that finding the best ordering is NP-hard in general (Variable elimination in Week 3). Even the best ordering can leave an intermediate factor over many variables at once, which is unreasonably costly. There is one large family of graphs where neither problem arises.

Definition. A graph \mathcal{G}=(\mathcal{V},\mathcal{E}) has a set of vertices (nodes) \mathcal{V} and a set of edges \mathcal{E}, with (i,j)\in\mathcal{E} when there is an edge between nodes i and j. The neighbours of node i are N(i) = \{j : (i,j)\in\mathcal{E}\}. An undirected graph is a tree if it is connected and has no cycles. A leaf is a node with exactly one neighbour.

The lecture’s informal picture: a tree is a chain that sometimes branches. For trees, any elimination ordering that works from the leaves inward toward some root is optimal. The reason is that summing out a leaf only touches the leaf itself and its single neighbour, so the intermediate factor it produces depends on one variable, the neighbour. Removing that leaf leaves a smaller tree, which has its own leaves, and the process repeats. No intermediate factor ever involves more than two variables at once, so with n variables of k states each the whole elimination costs O(nk^2), the same cost as the chain example of Week 3.

A tree-shaped Markov random field with one potential per node and one per edge has joint distribution

p(x_{1:n}) = \frac{1}{Z}\prod_{i\in\mathcal{V}}\psi_i(x_i)\prod_{(i,j)\in\mathcal{E}}\psi_{ij}(x_i,x_j).

The edges of a tree are its maximal cliques, so this is Week 3’s clique factorization (Markov random fields, cliques, and the factorization theorem in Week 3) with extra single-node potentials \psi_i added. An edge potential is one function of the pair, so we write its arguments in whichever order is convenient: \psi_{12}(x_1,x_2) and \psi_{12}(x_2,x_1) mean the same table read the same way.

TipRecap: Trees and elimination order

What the symbols stand for:

  • \mathcal{G} = (\mathcal{V}, \mathcal{E}): a graph with node set \mathcal{V} and edge set \mathcal{E}.
  • N(i): the neighbours of node i.
  • x_{1:n}: all n variables. k: the number of values each one takes.
  • \psi_i(x_i): a node potential, one score per value of x_i.
  • \psi_{ij}(x_i, x_j): an edge potential, one score per pair of values.

Taking the tree factorization apart:

p(x_{1:n}) = \frac{1}{Z}\prod_{i \in \mathcal{V}} \psi_i(x_i)\;\prod_{(i,j) \in \mathcal{E}} \psi_{ij}(x_i, x_j)

  • In a tree the maximal cliques are the edges, so the edge potentials are Week 3’s clique potentials. The node potentials are extra single-variable factors.
  • Summing out a leaf touches only its own potential and the one edge to its neighbour, so the leftover factor is over one variable. That is why the cost stays at O(nk^2).

A teaching example. Take a tree with n = 5 nodes, each with k = 3 values. A tree with 5 nodes has 4 edges. Storing the model takes 5 \times 3 = 15 node-potential entries and 4 \times 3^2 = 36 edge-potential entries, so 51 numbers. The full joint table would have 3^5 = 243 entries. Eliminating leaf by leaf costs about 5 \times 3^2 = 45 multiply-adds.

Worked example: elimination on a tree becomes message passing

The lecture’s example is a five-node tree: x_1 connects to x_2 and x_3, and x_3 connects to x_4 and x_5. The nodes x_2, x_4, x_5 are observed, with values written \bar x_2, \bar x_4, \bar x_5 (the bar marks an observed value, as in Week 3). We want p(x_3\mid\bar x_2,\bar x_4,\bar x_5).

Figure 1. The lecture’s tree. Blue nodes are observed, x_3 is the query variable, and x_1 is the only remaining variable, so it is the only one summed out.

Recall Week 3’s definition of inference (Exact inference as a conditional distribution in Week 3). Split the variables into the evidence x_E (observed), the query x_F (what we want), and the rest x_R (neither observed nor asked about). Inference computes

p(x_F\mid x_E) = \frac{p(x_F,x_E)}{\sum_{x_F} p(x_F,x_E)}, \qquad p(x_F,x_E) = \sum_{x_R} p(x_F,x_E,x_R).

In words: sum the joint over the variables we do not care about, then divide by the total over the query so the result sums to 1.

Here x_E = \{x_2, x_4, x_5\}, x_F = \{x_3\}, and x_R = \{x_1\}, since the only unobserved variable besides x_3 is x_1. So the answer is the joint with x_1 summed out, divided by a normalizer. The joint is the MRF’s product of potentials; its global constant 1/Z is the same for every x_3, so it is absorbed into the normalizer:

p(x_3\mid\bar x_2,\bar x_4,\bar x_5) = \frac{1}{Z^E}\sum_{x_1}\psi_1(x_1)\,\psi_3(x_3)\,\psi_2(\bar x_2)\,\psi_4(\bar x_4)\,\psi_5(\bar x_5) {}\times\psi_{12}(\bar x_2,x_1)\,\psi_{34}(\bar x_4,x_3)\,\psi_{35}(\bar x_5,x_3)\,\psi_{13}(x_1,x_3).

Here Z^E is whatever constant makes the right-hand side (everything to the right of the equals sign) sum to 1 when we add it up over all values of x_3; it depends on the evidence but not on x_3.

TipQuestion: How would we calculate the normalizer with real numbers?

Try it as a practice question. Use the same five-node tree, but make every variable binary, x_i \in \{0, 1\}. The evidence is already plugged in, so each potential that touches an observed node is a table over the unobserved variables only.

Potential Value when the free variable is 0 Value when it is 1
\psi_1(x_1) 1 2
\psi_3(x_3) 2 1
\psi_{12}(\bar x_2, x_1), as a function of x_1 1 4
\psi_{34}(\bar x_4, x_3), as a function of x_3 2 1
\psi_{35}(\bar x_5, x_3), as a function of x_3 1 3

The node potentials on the observed nodes are plain numbers: \psi_2(\bar x_2) = 3, \psi_4(\bar x_4) = 1, \psi_5(\bar x_5) = 2. The edge between the two unobserved nodes rewards agreement: \psi_{13}(x_1, x_3) = 3 when x_1 = x_3 and 1 when they differ.

Find Z^E, then p(x_3 = 1 \mid \bar x_2, \bar x_4, \bar x_5).

The equation we are working from. It is the two-line display above. Everything after the \frac{1}{Z^E} is a sum over x_1 of a product of nine factors. Call that whole sum f(x_3), the unnormalized answer, so the equation reads

p(x_3\mid\bar x_2,\bar x_4,\bar x_5) = \frac{f(x_3)}{Z^E}.

For the two probabilities to add to 1 we need f(0)/Z^E + f(1)/Z^E = 1, which means Z^E = f(0) + f(1). So the whole job is to compute f(0) and f(1) and add them.

Sorting the nine factors. Each factor depends on some of the variables in its brackets. The observed values \bar x_2, \bar x_4, \bar x_5 are fixed numbers, so the only things that can change are x_1 (which the sum runs over) and x_3 (the variable we are asking about). That splits the nine factors into three groups:

  • \psi_2(\bar x_2), \psi_4(\bar x_4), \psi_5(\bar x_5) contain no x_1 and no x_3. Each one is a single number. These are what we mean by “the constants”: they are the same in every term of the sum and for both values of x_3.
  • \psi_3(x_3), \psi_{34}(\bar x_4, x_3), \psi_{35}(\bar x_5, x_3) contain x_3 but not x_1.
  • \psi_1(x_1), \psi_{12}(\bar x_2, x_1), \psi_{13}(x_1, x_3) contain x_1.

A factor that does not change as x_1 changes can be pulled out of the sum over x_1, the same way a b + a c = a(b + c). Pulling out the first two groups gives

f(x_3) = \big[\psi_2(\bar x_2)\,\psi_4(\bar x_4)\,\psi_5(\bar x_5)\big]\times\big[\psi_3(x_3)\,\psi_{34}(\bar x_4,x_3)\,\psi_{35}(\bar x_5,x_3)\big] {}\times\sum_{x_1}\psi_1(x_1)\,\psi_{12}(\bar x_2,x_1)\,\psi_{13}(x_1,x_3).

The steps below compute the three pieces in turn.

Step 1: the constants (first bracket). 3 \times 1 \times 2 = 6. Because it is one number, we compute it once instead of inside every term.

Step 2: the sum over x_1 (last piece), for each value of x_3. With x_1 = 0, \psi_1\,\psi_{12} gives 1 \times 1 = 1; with x_1 = 1 it gives 2 \times 4 = 8. Each of those is then multiplied by \psi_{13}(x_1, x_3), which is 3 when x_1 = x_3 and 1 otherwise.

x_3 = 0:\quad 1 \times 3 + 8 \times 1 = 11 x_3 = 1:\quad 1 \times 1 + 8 \times 3 = 25

Step 3: the x_3-only factors (middle bracket), then multiply. \psi_3\,\psi_{34}\,\psi_{35} gives 2 \times 2 \times 1 = 4 at x_3 = 0 and 1 \times 1 \times 3 = 3 at x_3 = 1. Multiplying the three pieces gives f(x_3):

f(0) = 6 \times 4 \times 11 = 264 f(1) = 6 \times 3 \times 25 = 450

Step 4: normalize. Z^E = f(0) + f(1) = 264 + 450 = 714. Then

p(x_3 = 1 \mid \bar x_2, \bar x_4, \bar x_5) = \frac{450}{714} \approx 0.630, p(x_3 = 0 \mid \bar x_2, \bar x_4, \bar x_5) = \frac{264}{714} \approx 0.370.

Two things to notice. First, the constant 6 from Step 1 appears in both 264 and 450 and in Z^E, so it cancels: we could have dropped it and got Z^E = 44 + 75 = 119 with the same probabilities. This is why Z^E “depends on the evidence but not on x_3”. Second, the numbers 11 and 25 from Step 2 are the message m_{1\to3}(x_3) defined below, divided by \psi_2(\bar x_2) = 3. The message itself is 33 and 75, because m_{2\to1}(x_1) includes the factor 3 that Step 1 pulled out.

Now group the factors by which variable they mention, the same “push the sum inward” move as Week 3:

  • \psi_4(\bar x_4)\,\psi_{34}(\bar x_4,x_3) involves only x_3 (the x_4 value is fixed). Call it m_{4\to3}(x_3).
  • \psi_5(\bar x_5)\,\psi_{35}(\bar x_5,x_3) also involves only x_3. Call it m_{5\to3}(x_3).
  • \psi_2(\bar x_2)\,\psi_{12}(\bar x_2,x_1) involves only x_1. Call it m_{2\to1}(x_1).

None of the first two mention x_1, so they move outside the sum, leaving

p(x_3\mid\bar x_2,\bar x_4,\bar x_5) = \frac{1}{Z^E}\,\psi_3(x_3)\,m_{4\to3}(x_3)\,m_{5\to3}(x_3)\sum_{x_1}\psi_1(x_1)\,\psi_{13}(x_1,x_3)\,m_{2\to1}(x_1).

The remaining sum is a function of x_3 alone, because x_1 is the only thing it sums over. Call it m_{1\to3}(x_3):

m_{1\to3}(x_3) = \sum_{x_1}\psi_1(x_1)\,\psi_{13}(x_1,x_3)\,m_{2\to1}(x_1).

Substituting this into the line above gives a product of four factors, all functions of x_3. Call that product \tilde b(x_3):

\tilde b(x_3) = \psi_3(x_3)\,m_{1\to3}(x_3)\,m_{4\to3}(x_3)\,m_{5\to3}(x_3),

so that

p(x_3\mid\bar x_2,\bar x_4,\bar x_5) = \frac{1}{Z^E}\,\tilde b(x_3).

Where the sum in the denominator comes from. A probability distribution over x_3 must add to 1, so sum both sides over every value of x_3:

\sum_{x_3} p(x_3\mid\bar x_2,\bar x_4,\bar x_5) = \frac{1}{Z^E}\sum_{x_3}\tilde b(x_3) = 1.

The constant \frac{1}{Z^E} does not depend on x_3, so it comes out of the sum on the left. Solving for it gives Z^E = \sum_{x_3}\tilde b(x_3). Substituting that back in:

p(x_3\mid\bar x_2,\bar x_4,\bar x_5) = \frac{\tilde b(x_3)}{\sum_{x_3}\tilde b(x_3)}.

So the sum over x_3 in the denominator is not a new step. It is Z^E written out in terms of \tilde b, the same normalizer as before, now expressed through the messages instead of the raw potentials. The belief \tilde b(x_3) is named in Messages and beliefs.

The unnormalized product \tilde b(x_3) gets a name, the belief, in Messages and beliefs.

Each m is an intermediate factor \tau in Week 3’s sense (Sum-product inference: unifying DAGMs and MRFs in Week 3), but each one has a natural reading: it is a summary that one node sends to its neighbour about everything on its side of the tree. Node 2 summarizes its evidence for node 1; node 1 combines that with its own potential and summarizes the whole left branch for node 3; nodes 4 and 5 summarize their evidence for node 3.

A teaching example with binary nodes, all node potentials equal to 1, and every edge potential equal to 2 when its two ends agree and 1 when they differ. Observe \bar x_2 = 1, \bar x_4 = 1, \bar x_5 = 0. Write each message as (value at 0, value at 1).

  • m_{4\to3} = (1, 2), m_{5\to3} = (2, 1), m_{2\to1} = (1, 2).
  • m_{1\to3}(0) = 2 \cdot 1 + 1 \cdot 2 = 4 and m_{1\to3}(1) = 1 \cdot 1 + 2 \cdot 2 = 5.
  • \tilde b(x_3) = (4 \cdot 1 \cdot 2,\; 5 \cdot 2 \cdot 1) = (8, 10), so p(x_3 = 1 \mid \text{evidence}) = 10/18 \approx 0.56.

Nodes 4 and 5 disagree, so they cancel out. Node 2’s evidence, passed through node 1, tips x_3 slightly toward 1.

Messages and beliefs

The pattern in the worked example holds on any tree, so we can state it once for every edge.

Definition. In a tree-shaped MRF, the message from node j to a neighbour i\in N(j) is m_{j\to i}(x_i) = \sum_{x_j}\psi_j(x_j)\,\psi_{ij}(x_i,x_j)\prod_{k\in N(j)\setminus\{i\}} m_{k\to j}(x_j). If x_j is observed with value \bar x_j, the sum is replaced by plugging in that value: m_{j\to i}(x_i) = \psi_j(\bar x_j)\,\psi_{ij}(x_i,\bar x_j)\prod_{k\in N(j)\setminus\{i\}} m_{k\to j}(\bar x_j).

TipQuestion: How does the tree elimination become the message definition?

The general definition has three pieces. Take them one at a time, using the message from node 4 to node 3 in the worked example.

  • j is the node sending the message and i is the node receiving it. For m_{4\to3}, j = 4 and i = 3.
  • N(j)\setminus\{i\} is the set of j’s other neighbours. Node 4 has only one neighbour, node 3, so this set is empty.
  • Node 4 is observed, so the sum over x_4 is replaced by plugging in \bar x_4.

Putting these into the observed-node form gives

m_{4\to3}(x_3) = \psi_4(\bar x_4)\,\psi_{34}(x_3,\bar x_4)\prod_{k\in\varnothing} m_{k\to4}(\bar x_4) = \psi_4(\bar x_4)\,\psi_{34}(x_3,\bar x_4).

The product over an empty set is 1, so it drops out. What is left is the pair of factors the worked example groups together: \psi_4(\bar x_4)\,\psi_{34}(\bar x_4,x_3), which involves only x_3 because the x_4 value is fixed. The argument order inside \psi_{34} does not matter, since an undirected edge has no direction. The message m_{5\to3} follows the same pattern.

The message from node 1 uses the same definition with one more piece. Node 1 is unobserved, so its sum over x_1 stays in. Its other neighbour is node 2, so the product contributes m_{2\to1}(x_1):

m_{1\to3}(x_3) = \sum_{x_1}\psi_1(x_1)\,\psi_{13}(x_1,x_3)\,m_{2\to1}(x_1).

This is the sum over x_1 from the worked example. The only thing the general definition adds is the product over the other neighbours. That product is how a message carries a whole subtree rather than a single node.

In words, to send a message from j to i, node j does three things:

  1. Multiplies its own potential \psi_j by the messages from every other neighbour k \in N(j)\setminus\{i\}.
  2. Multiplies by the edge potential \psi_{ij} that connects j to i.
  3. Sums out its own variable x_j, which leaves a function of x_i only.

The message is the only thing that crosses the edge. Node i never sees x_j itself, so j passes along a summary of everything on its side of the edge that i needs. That is why it is called a message.

The exclusion k \neq i matters: j does not send back to i what i sent it, since i already knows that information. The product over k is what lets one message summarize an entire subtree rather than a single node. For a leaf j, the set N(j)\setminus\{i\} is empty, so the product is just 1.

Once node i has received a message from every neighbour, it combines all of them with its own potential. The result is its belief b(x_i): its current estimate of its own variable, using everything in the graph. The belief has no exclusion, because i has no one left to hold anything back from. That is why it is called a belief, not a message: it is i’s own answer, not something sent to a neighbour.

If x_i is discrete with K possible values, a message m_{j\to i}(x_i) is a vector with one entry for each value of x_i. It is not a probability distribution in general (it need not sum to 1), only a nonnegative score per state, like a potential.

Definition. Once node i has received a message from every neighbour, its belief is b(x_i) \propto \psi_i(x_i)\prod_{j\in N(i)} m_{j\to i}(x_i). In practice we compute an unnormalized belief \tilde b(x_i) = \psi_i(x_i)\prod_{j\in N(i)}m_{j\to i}(x_i), then normalize: b(x_i) = \tilde b(x_i)\big/\sum_{x_i}\tilde b(x_i).

The final line of the worked example in Worked example: elimination on a tree becomes message passing is exactly the belief at x_3, normalized. Since the messages reproduce variable elimination step for step, on a tree the normalized belief is the exact conditional marginal: here b(x_3) = p(x_3\mid\bar x_2,\bar x_4,\bar x_5).

Practice question: messages and beliefs on a three-node chain.

Given:

  • Binary spins x_1 - x_2 - x_3, each in \{+1,-1\}. Nothing is observed.
  • Edge potentials \psi_{12}(x_1,x_2) = e^{Jx_1x_2} and \psi_{23}(x_2,x_3) = e^{Jx_2x_3} with J = \log 2 (the Ising form from The Ising model in Week 3). Since x_ix_j is +1 when the spins agree and -1 when they differ, each edge potential is 2 when its endpoints agree and \tfrac12 when they differ.
  • Node potentials \psi_1(+1) = 3 and \psi_1(-1) = 1, and \psi_2(x_2) = \psi_3(x_3) = 1 for both values.

Find: the messages m_{1\to2}(x_2) and m_{2\to3}(x_3), the unnormalized belief \tilde b(x_3), the constant Z, and p(x_3 = +1) and p(x_3 = -1). Use the message definition above, and try it before opening the worked solution.

TipWorked solution

What we want: p(x_3). This is the marginal distribution of x_3: for each value of x_3, how likely it is, averaged over every possible x_1 and x_2. In the language of Week 3’s inference definition, x_F = \{x_3\}, there is no evidence, and x_R = \{x_1, x_2\}. The MRF joint is the product of all potentials divided by a constant Z:

p(x_1,x_2,x_3) = \frac{1}{Z}\,\psi_1(x_1)\,\psi_2(x_2)\,\psi_3(x_3)\,\psi_{12}(x_1,x_2)\,\psi_{23}(x_2,x_3).

Summing out x_1 and x_2 gives the marginal:

p(x_3) = \frac{1}{Z}\sum_{x_2}\sum_{x_1}\psi_1(x_1)\,\psi_2(x_2)\,\psi_3(x_3)\,\psi_{12}(x_1,x_2)\,\psi_{23}(x_2,x_3).

Pushing the sums inward. \psi_3(x_3) mentions neither x_1 nor x_2, so it comes out of both sums. Inside the sum over x_2, only \psi_1 and \psi_{12} mention x_1, so the sum over x_1 can wrap just those two:

p(x_3) = \frac{1}{Z}\,\psi_3(x_3)\sum_{x_2}\psi_2(x_2)\,\psi_{23}(x_2,x_3)\Big[\sum_{x_1}\psi_1(x_1)\,\psi_{12}(x_1,x_2)\Big].

The bracket is a function of x_2 only. It is the message m_{1\to2}(x_2). The whole sum over x_2 is then a function of x_3 only. It is the message m_{2\to3}(x_3). So we treat x_3 as the root and pass messages toward it, from the leaf x_1 inward.

Message 1: from x_1 to x_2. In the message definition, j = 1 (sender) and i = 2 (receiver). Node 1’s neighbours other than node 2 form the empty set, so the product of incoming messages is 1:

m_{1\to2}(x_2) = \sum_{x_1}\psi_1(x_1)\,\psi_{12}(x_1,x_2).

Evaluate it at each value of x_2, with one term per value of x_1 (first x_1 = +1, then x_1 = -1):

m_{1\to2}(+1) = \psi_1(+1)\,\psi_{12}(+1,+1) + \psi_1(-1)\,\psi_{12}(-1,+1) = 3\cdot 2 + 1\cdot\tfrac12 = 6.5, m_{1\to2}(-1) = \psi_1(+1)\,\psi_{12}(+1,-1) + \psi_1(-1)\,\psi_{12}(-1,-1) = 3\cdot\tfrac12 + 1\cdot 2 = 3.5.

Message 2: from x_2 to x_3. Now j = 2 and i = 3. Node 2’s other neighbour is node 1, so the product contains m_{1\to2}(x_2):

m_{2\to3}(x_3) = \sum_{x_2}\psi_2(x_2)\,\psi_{23}(x_2,x_3)\,m_{1\to2}(x_2).

With \psi_2 = 1, one term per value of x_2:

m_{2\to3}(+1) = 1\cdot 2\cdot 6.5 + 1\cdot\tfrac12\cdot 3.5 = 14.75, m_{2\to3}(-1) = 1\cdot\tfrac12\cdot 6.5 + 1\cdot 2\cdot 3.5 = 10.25.

The belief at x_3. Node 3’s only neighbour is node 2, so the belief definition gives

\tilde b(x_3) = \psi_3(x_3)\,m_{2\to3}(x_3) = (14.75,\ 10.25).

Comparing with the pushed-in formula, p(x_3) = \frac{1}{Z}\tilde b(x_3). Summing both sides over x_3 (the left side sums to 1) gives Z = \sum_{x_3}\tilde b(x_3) = 14.75 + 10.25 = 25. So

p(x_3 = +1) = \frac{14.75}{25} = 0.59, \qquad p(x_3 = -1) = \frac{10.25}{25} = 0.41.

As a check, adding up the unnormalized joint over all eight configurations of (x_1, x_2, x_3) also gives 25, so the messages found Z without listing the configurations.

Reading the result. The bias at x_1 toward +1 (3 to 1) has travelled down the chain, weakened at each edge because the coupling favours agreement without forcing it.

Scaling a message changes nothing. If we had normalized m_{1\to2} to (0.65,\ 0.35) before sending it, the next message would be

m_{2\to3}(+1) = 2\cdot 0.65 + \tfrac12\cdot 0.35 = 1.475, \qquad m_{2\to3}(-1) = \tfrac12\cdot 0.65 + 2\cdot 0.35 = 1.025.

Every entry is the earlier one divided by 10, so after normalizing the belief is still (0.59,\ 0.41). Scaling a message never changes a normalized belief, which is what makes the normalization trick of Loopy belief propagation safe.

TipRecap: Messages and beliefs

What the symbols stand for:

  • m_{j \to i}(x_i): the message from j to its neighbour i. One nonnegative number per value of x_i.
  • N(j) \setminus \{i\}: every neighbour of j except i.
  • \bar x_j: the observed value of x_j, if it is observed.
  • b(x_i): the belief at node i, its marginal once normalized. \tilde b(x_i) is the unnormalized version.

Taking the message formula apart:

m_{j\to i}(x_i) = \sum_{x_j}\psi_j(x_j)\,\psi_{ij}(x_i,x_j)\prod_{k\in N(j)\setminus\{i\}} m_{k\to j}(x_j)

  • The three pieces are everything node j knows apart from what i told it.
  • The sum over x_j removes j’s own variable, so the result depends only on x_i.
  • If x_j is observed, the sum becomes a single term at x_j = \bar x_j.
  • The belief is the node’s own score times every incoming message: \tilde b(x_i) = \psi_i(x_i)\prod_{j \in N(i)} m_{j\to i}(x_i).

A teaching example. Reuse the chain above (J = \log 2, so edges score 2 for agree and \tfrac12 for disagree, and \psi_1 = (3, 1) for (+1, -1)), but now observe x_1 = +1.

  • m_{1\to2}(x_2) = \psi_1(+1)\,\psi_{12}(x_2, +1) = 3 \cdot (2, \tfrac12) = (6, 1.5).
  • m_{2\to3}(+1) = 6 \cdot 2 + 1.5 \cdot \tfrac12 = 12.75 and m_{2\to3}(-1) = 6 \cdot \tfrac12 + 1.5 \cdot 2 = 6.
  • b(x_3 = +1) = 12.75 / 18.75 = 0.68.

Knowing x_1 = +1 for certain pushes x_3 further toward +1 than the soft lean in the unobserved example (0.59).

Belief propagation on trees

The worked example computed one marginal. If we want the marginal at every node, running variable elimination separately for each node would recompute the same messages over and over. Belief propagation computes each message once.

Definition. Belief propagation (BP), also called the sum-product algorithm on trees, is message passing between neighbouring nodes that computes all node marginals of a tree-shaped graphical model.

Belief propagation on a tree

  1. Choose a root r arbitrarily.
  2. Pass messages from the leaves to r: a node sends its message toward the root once it has heard from all its other neighbours.
  3. Pass messages from r back out to the leaves, using the same message formula.
  4. Compute every node’s belief b(x_i)\propto\psi_i(x_i)\prod_{j\in N(i)}m_{j\to i}(x_i) and normalize.

These two passes are sufficient on a tree. After the inward pass, the root has heard from every subtree. The outward pass then gives every other node the one message it was missing, the one from its parent’s side. At that point each node has a message from every neighbour, which is all the belief formula needs. A tree with |\mathcal{E}| edges needs exactly 2|\mathcal{E}| messages, one in each direction along each edge.

Figure 3. The tutorial’s tree with node 1 as root. Blue arrows are the inward pass (4 and 5 report to 2, then 2 and 3 report to 1); orange arrows are the outward pass. Four edges, eight messages.

TipRecap: Belief propagation on trees

What the symbols stand for:

  • r: the root, any node we choose.
  • |\mathcal{E}|: the number of edges. A tree with n nodes has n - 1.
  • b(x_i): the belief at node i, the same formula as Messages and beliefs.

Taking the algorithm apart:

  • Pass 1, leaves to root: each node waits until it has heard from all neighbours except the one toward the root, then sends to that one.
  • Pass 2, root to leaves: the root now has everything, so it sends back down. Each node then sends onward away from the root.
  • After both passes every node has one message from every neighbour, so every belief can be computed. Each edge carries one message in each direction, 2|\mathcal{E}| in total.

A teaching example. Finish the unobserved chain x_1 - x_2 - x_3 from Messages and beliefs (edges 2 if agree, \tfrac12 if not; \psi_1 = (3, 1), \psi_2 = \psi_3 = 1). Pass 1 already gave m_{1\to2} = (6.5, 3.5) and m_{2\to3}. Pass 2 sends the other two messages.

  • m_{3\to2}(x_2) = \sum_{x_3}\psi_{23}(x_2, x_3) = 2 + \tfrac12 = 2.5 for both values of x_2. A leaf with no preference sends a flat message.
  • \tilde b(x_2) = 1 \cdot (6.5, 3.5) \cdot 2.5, so b(x_2 = +1) = 0.65.
  • m_{2\to1}(x_1) = \sum_{x_2}\psi_{12}(x_1, x_2)\,m_{3\to2}(x_2) = 2.5 \cdot 2.5 = 6.25 for both values, so b(x_1 = +1) = 3/(3+1) = 0.75.

Four messages for two edges gave all three marginals: 0.75, 0.65, 0.59 for x_1 = +1, x_2 = +1, x_3 = +1.

Loopy belief propagation

What if the MRF has cycles? Then there are no leaves to start from, and “wait until you have heard from all other neighbours” never gets going, because every node on a cycle is waiting on another node on the same cycle. The lecture’s answer is to apply the message updates anyway and keep passing messages until they settle down.

Loopy belief propagation

  1. Initialize every message uniformly: m_{i\to j}(x_j) = [1/k,\dots,1/k]^\top, where k is the number of states x_j can take.
  2. Repeatedly sweep through the edges, recomputing each message with the usual update m_{j\to i}(x_i) = \sum_{x_j}\psi_j(x_j)\,\psi_{ij}(x_i,x_j)\prod_{k\in N(j)\setminus\{i\}} m_{k\to j}(x_j), often normalizing each new message so its entries sum to 1, until the messages (approximately) stop changing or an iteration budget runs out.
  3. Compute beliefs b(x_i)\propto\psi_i(x_i)\prod_{j\in N(i)}m_{j\to i}(x_i).

The result is loopy belief propagation. Its beliefs are approximations to the marginals, not the exact marginals, and the lecture is candid about its limitations:

  • No general guarantee. It is guaranteed to give exact answers only on trees and in some special cases. It may not converge at all, and the messages may oscillate. In practice this is generally acceptable: the tutorial reports that 10–20 iterations are enough for useful approximate inference.
  • Over-confidence. On a cycle, a node’s own evidence leaves along one edge and returns along another, so the same potentials get multiplied in more than once. The lecture compares this to someone who starts a rumour, then hears the same rumour back from someone else and becomes more certain it is true. Beliefs from loopy BP are therefore often more peaked than the true marginals.
  • Stabilizing tricks. Loopy BP often works better if messages are normalized (shown in Messages and beliefs to leave beliefs unchanged on a tree) and if updates use momentum: rather than replacing a message outright, move it part of the way toward the newly computed value, m^{\text{new}}_{j\to i}(x_i) = (1-\alpha)\,m^{\text{old}}_{j\to i}(x_i) + \alpha\,\big[\text{update}\big], with a step size \alpha\in(0,1]. Smaller \alpha damps the oscillations described above.

Despite the lack of guarantees, loopy BP is widely used in practice, and the tutorial’s denoising example below is one illustration.

TipRecap: Loopy belief propagation

What the symbols stand for:

  • [1/k, \dots, 1/k]^\top: a uniform starting message, the same score for each of the k values.
  • m^{\text{old}}_{j\to i}: the message from the previous sweep. [\text{update}]: the message the usual formula gives now.
  • \alpha \in (0, 1]: the momentum step size, how far we move toward the new value.

Taking the equations apart:

  • The message update is the tree formula from Messages and beliefs, unchanged. Only the schedule differs: on a cycle no node ever “hears from everyone first”, so every message is recomputed over and over from the current values of the others.
  • Normalizing a message rescales it to sum to 1. On a tree this never changed a belief, and here it keeps numbers from growing or shrinking without bound.
  • m^{\text{new}} = (1 - \alpha)\,m^{\text{old}} + \alpha\,[\text{update}] is a weighted average. \alpha = 1 means “replace”. Smaller \alpha means “move part of the way”.

A teaching example of one momentum step. A normalized message is m^{\text{old}} = (0.5, 0.5) and the formula now gives (0.8, 0.2). With \alpha = 0.3:

m^{\text{new}} = 0.7\,(0.5, 0.5) + 0.3\,(0.8, 0.2) = (0.59, 0.41).

The message moves 30% of the way. If the next update swung back to (0.2, 0.8), the damped message would be 0.7(0.59, 0.41) + 0.3(0.2, 0.8) = (0.473, 0.527), a small swing instead of a full flip. Both results still sum to 1, because a weighted average of normalized vectors is normalized.

Max-product BP and MAP inference

Everything so far computes marginals: for each node, a distribution over its states. Sometimes we want something else: the single most likely joint setting of the unobserved variables.

Definition. The maximum a posteriori (MAP) estimate is the most probable value of the unobserved variables given the evidence, \arg\max_{x_F} p(x_F\mid x_E). MAP inference is the task of computing it.

The algorithm we have been using is more precisely called sum-product BP, because each message is a sum of products. For MAP inference we maximize over x_j instead of summing, which gives max-product BP:

m_{j\to i}(x_i) = \max_{x_j}\ \psi_j(x_j)\,\psi_{ij}(x_i,x_j)\prod_{k\in N(j)\setminus\{i\}} m_{k\to j}(x_j).

The resulting beliefs b(x_i)\propto\psi_i(x_i)\prod_{j\in N(i)}m_{j\to i}(x_i) are now max-marginals: b(x_i) scores the best joint configuration that has node i in state x_i, rather than the total probability of all configurations with node i in that state. The MAP estimate is then read off node by node:

\hat x_i = \arg\max_{x_i}\, b(x_i).

The swap works for the same reason sum-product works: on a tree, a maximum distributes over a product of nonnegative factors exactly as a sum does, so the same “push the operation inward past factors that do not mention x_j” argument goes through with \max in place of \sum. (Reading off \hat x_i node by node is safe when each node’s maximizer is unique; ties need extra bookkeeping that the lecture does not cover.)

TipRecap: Max-product BP and MAP inference

What the symbols stand for:

  • \arg\max_{x_F} p(x_F \mid x_E): the MAP estimate, the single most probable joint setting of the unobserved variables.
  • \max_{x_j}: take the largest value over x_j, instead of adding over it.
  • b(x_i): now a max-marginal, the score of the best full setting that has node i in state x_i.
  • \hat x_i: the MAP value of node i.

Taking the change apart:

  • Sum-product asks “how much total probability has x_i in this state?” Max-product asks “how good is the best setting with x_i in this state?”
  • The message formula is the same except \sum_{x_j} becomes \max_{x_j}.
  • Reading off \hat x_i = \arg\max b(x_i) at every node gives a jointly best setting, not a collection of separately best guesses.

A teaching example. Two binary nodes, \psi_1 = \psi_2 = 1, edge potential \psi_{12}(0,0) = 6, \psi_{12}(0,1) = 1, \psi_{12}(1,0) = 4, \psi_{12}(1,1) = 4. The joint MAP is (0, 0) with score 6.

  • Sum-product marginal of x_1: (6 + 1,\; 4 + 4) = (7, 8), so x_1 = 1 is more probable on its own. For x_2: (6 + 4,\; 1 + 4) = (10, 5), favouring x_2 = 0. Combining the separate winners gives (1, 0), which scores only 4.
  • Max-marginal of x_1: (\max(6, 1),\; \max(4, 4)) = (6, 4), so \hat x_1 = 0. For x_2: (\max(6, 4),\; \max(1, 4)) = (6, 4), so \hat x_2 = 0. Max-product recovers the MAP (0, 0).

Tutorial example: image denoising with loopy BP

The tutorial applies loopy BP to a concrete problem. A binary image is a \sqrt{n}\times\sqrt{n} grid of pixels, each +1 or -1, which we flatten into a vector x\in\{-1,+1\}^n. The tutorial’s example is a 128\times128 black-and-white Mona Lisa, so n=16384.

The image is sent through a noisy channel that flips each pixel independently with a small probability \epsilon (a binary symmetric channel). The true pixels x are latent; we observe the noisy pixels y. The goal is to recover x from y.

Figure 4. A small corner of the denoising model. Each true pixel x_s (green, latent) is linked to its grid neighbours by an Ising edge and to its own noisy observation y_s (blue, observed). The grid contains many 4-cycles, so exact BP does not apply and the tutorial uses loopy BP.

The observation model. One pixel’s observation agrees with the truth (y_sx_s=+1) with probability 1-\epsilon and disagrees (y_sx_s=-1) with probability \epsilon. Since \tfrac{1+y_sx_s}{2} is 1 on agreement and 0 on disagreement, this can be written as a single formula and rearranged into Ising form:

\mathbb{P}(y_s\mid x_s) = (1-\epsilon)^{\frac{1+y_sx_s}{2}}\,\epsilon^{\frac{1-y_sx_s}{2}} = \exp\Big\{\tfrac{1+y_sx_s}{2}\log(1-\epsilon) + \tfrac{1-y_sx_s}{2}\log\epsilon\Big\} \propto \exp\Big\{y_sx_s\cdot\tfrac12\log\Big(\frac{1-\epsilon}{\epsilon}\Big)\Big\} = \exp\{\beta\,y_sx_s\}, \beta = \tfrac12\log\Big(\frac{1-\epsilon}{\epsilon}\Big).

The \propto step drops \tfrac12\log(1-\epsilon)+\tfrac12\log\epsilon, which does not depend on x_s. When the noise is small, \epsilon<\tfrac12 makes \beta>0, so the model rewards each true pixel for agreeing with its observation; the smaller \epsilon, the larger \beta and the stronger that pull.

The prior. Natural images tend to have neighbouring pixels of the same colour, so the prior on x is an Ising model on the grid (The Ising model in Week 3) with coupling J>0:

p(x)\propto\prod_{s\sim t}\psi_{st}(x_s,x_t), \qquad \psi_{st}(x_s,x_t) = \exp(Jx_sx_t) = \begin{pmatrix} e^{J} & e^{-J}\\ e^{-J} & e^{J}\end{pmatrix},

where s\sim t ranges over grid edges, and the matrix lists the potential’s values with rows and columns ordered (+1,-1).

The posterior. Combining prior and observations with Bayes’ rule, and using that pixels are flipped independently,

p(x\mid y)\propto p(x,y) = p(x)\prod_s p(y_s\mid x_s) \propto \exp\Big\{J\sum_{s\sim t}x_sx_t + \beta\sum_s y_sx_s\Big\} = \prod_{s\sim t}\psi_{st}(x_s,x_t)\prod_s\psi_s(x_s), \qquad \psi_s(x_s) = \exp(\beta y_sx_s).

So the posterior over the true image is itself an Ising MRF on the grid, with the observations entering only as node potentials. That is exactly the form BP needs.

Running loopy BP. Each message m_{j\to i}(x_i) is stored as a 2-vector \big(m_{j\to i}(+1),\ m_{j\to i}(-1)\big), and each belief likewise. Initialize every message to (\tfrac12,\tfrac12), run the loopy updates of Loopy belief propagation (summing over x_j\in\{-1,+1\}) with normalization, then compute beliefs. The tutorial reports that 10–20 iterations suffice, and the beliefs approximate the posterior marginals p(x_i\mid y). One decision rule is \hat x_i = \arg\max_{x_i} b(x_i), which picks whichever colour each pixel’s approximate marginal favours. In the tutorial’s Mona Lisa example, this recovers a clean image from one with a large fraction of flipped pixels.

TipRecap: Tutorial example: image denoising with loopy BP

What the symbols stand for:

  • x_s \in \{-1, +1\}: the true colour of pixel s (latent). y_s: the noisy colour we observe.
  • \epsilon: the probability that the channel flips a pixel.
  • \beta = \tfrac12\log\frac{1-\epsilon}{\epsilon}: how strongly each true pixel is pulled toward its observation.
  • J > 0: how strongly neighbouring true pixels are pulled toward each other.
  • \psi_s(x_s) = e^{\beta y_s x_s}: the node potential built from the observation.

Taking the equations apart:

  • \frac{1 + y_s x_s}{2} is 1 on agreement and 0 on disagreement, so the first line picks 1 - \epsilon or \epsilon with one formula.
  • Rewriting as e^{\beta y_s x_s} turns the observation into an Ising field: agreement adds \beta to the exponent, disagreement subtracts it.
  • The posterior exponent J\sum_{s\sim t} x_s x_t + \beta\sum_s y_s x_s has two competing rewards: match your neighbours, and match your observation.

A teaching example with a single pixel and no neighbours, to check that \beta is the right strength. Let \epsilon = 0.1. Then \beta = \tfrac12\log 9, so e^{\beta} = 3. If we observe y_s = +1:

p(x_s = +1 \mid y_s) = \frac{e^{\beta}}{e^{\beta} + e^{-\beta}} = \frac{3}{3 + 1/3} = 0.9 = 1 - \epsilon.

With no neighbours, the posterior just trusts the channel. In the full grid, the J terms let neighbours outvote a pixel’s own observation when they disagree with it.

Sampling from an unnormalized density

The second half of the lecture changes approach. Instead of computing sums exactly or approximately with messages, we draw random samples and average over them.

Definition. A sample from a distribution p(x) is a single realization x whose probability distribution is p(x). Here x may be a single real number or a high-dimensional vector.

Throughout, we assume we can evaluate p(x) only up to a multiplicative constant. That is, we can compute a function \tilde p(x) with

p(x) = \frac{\tilde p(x)}{Z}, \qquad Z = \int\tilde p(x)\,dx,

but we do not know Z. This is the normal situation for the models in this course: an MRF’s product of potentials is \tilde p, and its partition function Z (Markov random fields, cliques, and the factorization theorem in Week 3) is exactly the hard part. The posterior of Tutorial example: image denoising with loopy BP is another example, since we wrote it only up to \propto.

TipRecap: Sampling from an unnormalized density

What the symbols stand for:

  • p(x): the distribution we want samples from.
  • \tilde p(x): a function we can compute, equal to p(x) times an unknown constant.
  • Z = \int \tilde p(x)\,dx: that constant, the total area under \tilde p.

Taking p(x) = \tilde p(x)/Z apart:

  • \tilde p has the right shape: it is high where p is high and low where p is low.
  • Dividing by Z only fixes the scale so the total is 1. Ratios such as p(a)/p(b) = \tilde p(a)/\tilde p(b) never need Z.

A teaching example. Take \tilde p(x) = e^{-x^2/2}. We can evaluate it anywhere: \tilde p(0) = 1 and \tilde p(1) \approx 0.607. So x = 0 is about 1/0.607 \approx 1.65 times as likely as x = 1, with no Z in sight. In this case we happen to know Z = \sqrt{2\pi} \approx 2.507 (it is the standard Gaussian), but for an MRF over thousands of variables there is no such formula.

Ancestral sampling

Sampling is easiest in a directed model. The idea relies on one ordering concept.

Definition. A topological order of a DAG is an ordering of its nodes in which every node comes after all of its parents.

Definition. Given a DAG and the ability to sample from each node’s conditional distribution given its parents, ancestral sampling draws a sample from the joint distribution by visiting the nodes in a topological order and sampling each one from p(x_i\mid\text{parents}(x_i)) with its parents set to the values already drawn.

This works because a DAG’s joint factorizes into exactly these conditionals (Directed graphical models in Week 2), so sampling them in turn produces a draw from the product.

Figure 5. The lecture’s ancestral-sampling example. Each node is sampled only after all of its parents.

Worked example. The DAG in Figure 5 factorizes as

p(x_1,\dots,x_5) = p(x_1)\,p(x_2\mid x_1)\,p(x_3\mid x_1)\,p(x_4\mid x_2,x_3)\,p(x_5\mid x_3).

Sample x_1 from p(x_1). Then sample x_2 from p(x_2\mid x_1) and x_3 from p(x_3\mid x_1), plugging in the drawn x_1. Then sample x_4 from p(x_4\mid x_2,x_3). Finally, sample x_5 from p(x_5\mid x_3). (Any order in which parents precede children would do; x_5 could equally come before x_4.)

Ancestral sampling draws from the joint with nothing observed. It does not directly give samples from a conditional such as p(x_1\mid x_4), and it needs a directed model with easy-to-sample conditionals; an MRF with an unknown Z offers neither. The rest of the lecture deals with that harder setting.

TipRecap: Ancestral sampling

What the symbols stand for:

  • Topological order: any listing of the nodes in which each node comes after its parents.
  • p(x_i \mid \text{parents}(x_i)): node i’s conditional table, which we can sample from once its parents have values.

Taking the factorization apart:

  • p(x_1) has no parents, so it is sampled first.
  • p(x_2 \mid x_1) and p(x_3 \mid x_1) only need x_1, which we now have.
  • p(x_4 \mid x_2, x_3) needs both x_2 and x_3, and p(x_5 \mid x_3) needs x_3.
  • Following the product left to right, every factor’s conditioning values have already been drawn.

A teaching example on Figure 5 with binary nodes. The probabilities and uniform draws below are invented for illustration. The lecture does not derive them from a fitted model, and we chose the draws by hand instead of using a random number generator.

Each binary node is sampled by comparing a uniform draw to its probability of being 1. Write \pi_i for the table entry that node i uses, given the parent values already drawn:

\pi_i = p(x_i{=}1 \mid \text{parents}(x_i)), \qquad x_i = \begin{cases} 1 & \text{if } u_i < \pi_i, \\ 0 & \text{otherwise,} \end{cases} \qquad u_i \sim \text{Uniform}[0,1].

This gives the right conditional probability. Because \mathbb{P}(u_i < \pi_i) = \pi_i for a uniform u_i, we have \mathbb{P}(x_i{=}1 \mid \text{parents}(x_i)) = \pi_i. So the table value p(x_1{=}1) = 0.4 is used directly: it is the threshold that u_1 is compared against. Each table entry is used exactly once, at the node it belongs to.

Applying the rule to the draws u = (0.25, 0.9, 0.1, 0.35, 0.95):

  • \pi_1 = p(x_1{=}1) = 0.4. Since u_1 = 0.25 < 0.4, x_1 = 1.
  • \pi_2 = p(x_2{=}1 \mid x_1{=}1) = 0.7. Since u_2 = 0.9 is not less than 0.7, x_2 = 0.
  • \pi_3 = p(x_3{=}1 \mid x_1{=}1) = 0.5. Since u_3 = 0.1 < 0.5, x_3 = 1.
  • \pi_4 = p(x_4{=}1 \mid x_2{=}0, x_3{=}1) = 0.6. Since u_4 = 0.35 < 0.6, x_4 = 1.
  • \pi_5 = p(x_5{=}1 \mid x_3{=}1) = 0.8. Since u_5 = 0.95 is not less than 0.8, x_5 = 0.

One sample is (1, 0, 1, 1, 0). Its probability under the model is the product of the factors evaluated at the sampled values. A node that came out 0 contributes 1 - \pi_i, which is why p(x_2{=}0 \mid x_1{=}1) = 0.3 and not 0.7:

\begin{aligned} p(x_1{=}1, x_2{=}0, x_3{=}1, x_4{=}1, x_5{=}0) &= p(x_1{=}1)\, p(x_2{=}0 \mid x_1{=}1)\, p(x_3{=}1 \mid x_1{=}1)\, p(x_4{=}1 \mid x_2{=}0, x_3{=}1)\, p(x_5{=}0 \mid x_3{=}1) \\ &= 0.4 \times 0.3 \times 0.5 \times 0.6 \times 0.2 = 0.0072. \end{aligned}

This product is a check on the factorization. It is not an input to sampling: the draws only needed the thresholds \pi_i.

What sampling is for

The lecture names two problems that Monte Carlo methods solve:

  • Problem 1: generate samples \{x^{(r)}\}_{r=1}^R from a given distribution p(x).
  • Problem 2: estimate the expectation of a function under p, \Phi = \mathbb{E}_{x\sim p(x)}[\phi(x)] = \int\phi(x)\,p(x)\,dx.

Definition. The function \phi whose expectation we want in Problem 2 is called a test function.

Different test functions answer different questions. For a function f of interest:

  • the mean of f under p is the expectation of \phi_1(x)=f(x), giving \Phi_1;
  • the variance of f needs a second test function \phi_2(x)=f(x)^2, giving \Phi_2, and then \mathrm{var}(f(x)) = \Phi_2 - (\Phi_1)^2.

Probabilities are expectations too: \mathbb{P}(x\in A) = \mathbb{E}[\mathbf{1}_{\{x\in A\}}], using the indicator function \mathbf{1}_{\{x\in A\}}, which is 1 when x\in A and 0 otherwise. This fact is used again in the rejection-sampling proof below.

TipRecap: What sampling is for

What the symbols stand for:

  • \{x^{(r)}\}_{r=1}^R: R samples. The superscript (r) counts samples, not powers.
  • \phi(x): the test function, whatever quantity of x we want the average of.
  • \Phi = \mathbb{E}_{x\sim p}[\phi(x)]: that average under p.
  • \mathbf{1}_{\{x \in A\}}: the indicator, 1 if x is in set A and 0 otherwise.

Taking the equations apart:

  • \Phi = \int \phi(x)\,p(x)\,dx: weight each value of the test function by how likely x is, and add.
  • Mean: use \phi_1 = f. Variance: also compute \phi_2 = f^2, then \Phi_2 - \Phi_1^2 (average of the square minus square of the average).
  • Probability of a set: use \phi = \mathbf{1}_{\{x\in A\}}. Its average is the fraction of probability inside A.

A teaching example with a fair six-sided die and f(x) = x.

  • \Phi_1 = (1+2+3+4+5+6)/6 = 3.5.
  • \Phi_2 = (1+4+9+16+25+36)/6 = 91/6 \approx 15.17, so the variance is 15.17 - 3.5^2 \approx 2.92.
  • \mathbb{P}(x \ge 5) = \mathbb{E}[\mathbf{1}_{\{x \ge 5\}}] = (0+0+0+0+1+1)/6 = 1/3.

Three different questions, all answered as an average of some test function.

Simple Monte Carlo

If we already have samples from p (Problem 1 solved), Problem 2 has a direct answer: average the test function over the samples.

Definition. Given samples \{x^{(r)}\}_{r=1}^R\sim p(x), the simple Monte Carlo estimator of \Phi=\mathbb{E}_{x\sim p(x)}[\phi(x)] is \hat\Phi = \frac1R\sum_{r=1}^R\phi(x^{(r)}).

Two standard properties of an estimator tell us whether this is a good idea. An estimator is unbiased if its expected value equals the quantity it estimates, and consistent if it converges to that quantity as the number of samples grows. The law of large numbers, which says an average of i.i.d. draws converges to their common mean, gives consistency of \hat\Phi directly. The other two properties follow from short calculations.

Unbiasedness. If the samples are drawn independently from p, linearity of expectation gives

\mathbb{E}[\hat\Phi] = \frac1R\sum_{r=1}^R\mathbb{E}\big[\phi(x^{(r)})\big] = \frac1R\sum_{r=1}^R\mathbb{E}_{x\sim p(x)}\big[\phi(x)\big] = \frac{R}{R}\,\Phi = \Phi.

Variance. Pulling the constant \tfrac1R out squares it, and the variance of a sum of independent terms is the sum of their variances:

\mathrm{var}[\hat\Phi] = \frac{1}{R^2}\,\mathrm{var}\Big[\sum_{r=1}^R\phi(x^{(r)})\Big] = \frac{1}{R^2}\sum_{r=1}^R\mathrm{var}\big[\phi(x^{(r)})\big] = \frac{R}{R^2}\,\mathrm{var}[\phi(x)] = \frac1R\,\mathrm{var}[\phi(x)].

So the variance of the estimate shrinks at rate 1/R, and its accuracy depends on \mathrm{var}[\phi(x)], the spread of the test function under p. Notice what does not appear: the dimension of x. For example, if \mathrm{var}[\phi(x)]=4, then R=100 samples give \mathrm{var}[\hat\Phi]=0.04, a standard deviation of 0.2, and quadrupling to R=400 halves that standard deviation to 0.1. This dimension-free rate is what makes sampling attractive, provided we can get the samples.

  • \mathrm{var}[\hat\Phi]: how much the estimate wobbles from one repetition to the next.

Why the normalizing constant is hard

When we can only evaluate \tilde p, there are two separate difficulties:

  1. We generally do not know Z=\int\tilde p(x)\,dx, and computing it is a high-dimensional integral.
  2. Even if we knew Z, drawing samples from p is still challenging, especially in high dimensions.

A bad idea: lattice discretization. One way to approximate Z is to evaluate \tilde p on a grid of points and add up the values (and to sample, pick a grid point with probability proportional to \tilde p there). The lecture’s example uses 50 evenly spaced points in one dimension, which describes a one-dimensional density well. But a grid with 50 points per axis in D dimensions has 50^D points: for D=1000, that is 50^{1000}. The cost is exponential in dimension, an instance of the curse of dimensionality.

The lecture’s lake analogy. Imagine drawing water samples from a lake to find the average plankton concentration. Let \tilde p(\boldsymbol{x}) be the depth of the lake at location \boldsymbol{x}=(x,y), \phi(\boldsymbol{x}) the plankton concentration there, and Z=\int\tilde p(\boldsymbol{x})\,d\boldsymbol{x} the volume of the lake. The average concentration over the lake’s water is

\Phi = \frac1Z\int\phi(\boldsymbol{x})\,\tilde p(\boldsymbol{x})\,d\boldsymbol{x}.

We can take a boat to any location and measure both the depth \tilde p(\boldsymbol{x}) and the concentration \phi(\boldsymbol{x}) there. Problem 1 is to draw water samples so that each is equally likely to come from any point within the lake’s volume. Problem 2 is to find the average concentration. The difficulty is a lake with a few narrow, very deep canyons: they hold much of the water, but a boat visiting surface locations at random rarely lands on one. To estimate \Phi correctly, a method must implicitly discover the canyons and find their volume relative to the rest of the lake. High-dimensional distributions behave the same way, with most of their probability mass concentrated in regions that are a tiny fraction of the space.

TipQuestion: Where does the 1/Z in this average come from?

It is the ordinary definition of an expectation, \Phi=\int\phi(x)\,p(x)\,dx, with p=\tilde p/Z substituted. Z does not depend on x, so it is a constant inside the integral and comes out by linearity: \Phi=\int\phi(x)\,\frac{\tilde p(x)}{Z}\,dx=\frac1Z\int\phi(x)\,\tilde p(x)\,dx. In the lake picture, the integral is the total plankton (concentration times depth, added up) and Z is the volume of water, so \Phi is total divided by volume.

A small check. Let x\in\{1,2,3\} with \tilde p=(1,2,3), so Z=6, and take \phi(x)=x^2. The ratio form gives (1\cdot1+4\cdot2+9\cdot3)/6=36/6=6. Using p=(\tfrac16,\tfrac26,\tfrac36) directly gives \tfrac16+\tfrac86+\tfrac{27}6=6, the same number.

Two tests for a missing Z.

  • With \phi\equiv1 the average must be 1. Without the division we would get \sum\tilde p=6 instead.
  • Doubling \tilde p doubles both the numerator and Z (72/12=6), so the ratio is unchanged. The overall scale of \tilde p never matters, but the denominator does, which is why importance sampling (Importance sampling) needs an estimate of a ratio of normalizers.

Importance sampling

Importance sampling is a tool for Problem 2, estimating \Phi=\mathbb{E}_p[\phi(x)], when we cannot sample from p. The setup:

  • The target density can be evaluated up to a constant: p(x) = \tilde p(x)/Z_p.
  • There is a simpler proposal density q(x) = \tilde q(x)/Z_q that we can both sample from and evaluate up to a constant.

Draw R samples \{x^{(r)}\}_{r=1}^R\sim q(x). If they had come from p, simple Monte Carlo would apply. They did not: values of x where q(x)>p(x) are over-represented, and values where q(x)<p(x) are under-represented. The fix is to weight each sample.

Definition. The importance weight of sample x^{(r)} is \tilde w_r = \dfrac{\tilde p(x^{(r)})}{\tilde q(x^{(r)})}, and the normalized weights are w_r = \dfrac{\tilde w_r}{\sum_{r'=1}^R\tilde w_{r'}}.

The weights estimate the ratio of normalizers. The average weight is a simple Monte Carlo estimate under q:

\frac1R\sum_{r=1}^R\tilde w_r \approx \mathbb{E}_{x\sim q(x)}\Big[\frac{\tilde p(x)}{\tilde q(x)}\Big] = \int\frac{Z_p\,p(x)}{Z_q\,q(x)}\,q(x)\,dx = \frac{Z_p}{Z_q}.

Correcting the estimate of \Phi. Multiply and divide by q inside the integral, then estimate with the samples from q:

\Phi = \int\phi(x)\,p(x)\,dx = \int\phi(x)\,\frac{p(x)}{q(x)}\,q(x)\,dx \approx \frac1R\sum_{r=1}^R\phi(x^{(r)})\,\frac{p(x^{(r)})}{q(x^{(r)})}.

Replacing p/q with \tilde p/\tilde q introduces the unknown ratio Z_q/Z_p:

\frac1R\sum_{r=1}^R\phi(x^{(r)})\,\frac{p(x^{(r)})}{q(x^{(r)})} = \frac{Z_q}{Z_p}\cdot\frac1R\sum_{r=1}^R\phi(x^{(r)})\,\tilde w_r.

Finally, replace Z_q/Z_p by the reciprocal of its estimate from the average weight. The two factors of \tfrac1R cancel:

\Phi \approx \frac{\frac1R\sum_{r=1}^R\phi(x^{(r)})\,\tilde w_r}{\frac1R\sum_{r=1}^R\tilde w_r} = \sum_{r=1}^R\phi(x^{(r)})\,w_r.

The estimate is a weighted average of the test function over samples from q, where each sample’s weight says how much more (or less) likely it is under p than under q. Neither Z_p nor Z_q is ever needed. Because the last step divides one estimate by another, this self-normalized estimator is not exactly unbiased for finite R, but it is consistent as R grows. Its accuracy depends on how well q covers p: if q puts very little mass where p has a lot (a missed canyon, in the lake picture), a few samples with huge weights dominate the sum.

TipRecap: Importance sampling

What the symbols stand for:

  • p = \tilde p / Z_p: the target, which we can evaluate up to Z_p but cannot sample.
  • q = \tilde q / Z_q: the proposal, which we can sample and evaluate up to Z_q.
  • \tilde w_r = \tilde p(x^{(r)}) / \tilde q(x^{(r)}): the importance weight of sample r.
  • w_r = \tilde w_r / \sum_{r'}\tilde w_{r'}: the normalized weight. The w_r sum to 1.

Taking the final estimator apart:

\Phi \approx \frac{\sum_r \phi(x^{(r)})\,\tilde w_r}{\sum_r \tilde w_r} = \sum_r w_r\,\phi(x^{(r)})

  • A sample that p likes more than q does gets a weight above average. One that q over-produces gets a weight below average.
  • The numerator is a weighted total of the test function. The denominator rescales the weights to sum to 1.
  • Dividing removes both unknown constants, because Z_p and Z_q appear equally on top and bottom.

A teaching example. The target on \{1, 2, 3\} has \tilde p = (1, 2, 3), so the true \Phi for \phi(x) = x^2 is 6 (see the dropdown on 1/Z above). The proposal is uniform, \tilde q = (1, 1, 1). Four draws from q are 1, 3, 3, 2, with weights \tilde w = 1, 3, 3, 2.

\hat\Phi = \frac{1(1) + 9(3) + 9(3) + 4(2)}{1 + 3 + 3 + 2} = \frac{63}{9} = 7.

With only four samples the estimate is off by 1, but it improves as R grows. As a side product, the average weight 9/4 = 2.25 estimates Z_p/Z_q = 6/3 = 2.

TipQuestion: What problem does importance sampling solve, and how does it differ from regular Monte Carlo?

The idea in plain terms. We want an average over some population, but we cannot pick members of that population fairly at random. What we can do is pick members in some other, convenient way, and for each one we pick, measure how much it should count. Importance sampling then takes a weighted average: members that the convenient method under-represents count for more, and members it over-represents count for less. Regular Monte Carlo is the special case where we could pick fairly in the first place, so every member counts once.

The proposal q is chosen before any sampling, because it is easy to draw from. It is not built from the samples. The samples come out of q, and the weights are then computed one sample at a time.

What we are given, and what we get.

In general In the lake
Want \Phi = \mathbb{E}_p[\phi(x)] the average plankton concentration over all the lake’s water
Cannot do sample from p, or compute Z_p pick a drop of water uniformly from the whole volume, or know the volume
Can do evaluate \tilde p(x) and \phi(x) at any single x we choose go to a spot and measure its depth and its plankton
Can do sample from a proposal q pick a spot on the surface uniformly at random
Get a weighted estimate of \Phi, and of Z_p/Z_q an estimate of the average concentration, and of the average depth

So we never know p as a whole. We only learn \tilde p at the handful of points we actually visit, one measurement at a time. We also never know the true \Phi: estimating it is the whole purpose.

The problem. Return to the lake from Why the normalizing constant is hard. A survey team wants the average plankton concentration in the lake’s water. Plankton is not spread evenly, so the answer depends on where the water is. A deep spot holds more water than a shallow one and should count for more.

Regular Monte Carlo would need water samples drawn uniformly from the lake’s volume, so that every drop is equally likely. That is Problem 1, and the team cannot do it: choosing a drop uniformly requires already knowing the shape of the lakebed everywhere.

What the team can do is pick spots uniformly on the surface (a map and a random number generator are enough) and, at each spot, lower a line to read the depth \tilde p(\boldsymbol{x}) and take a reading of the concentration \phi(\boldsymbol{x}). Surface spots are the proposal: \tilde q(\boldsymbol{x}) = 1 everywhere on the surface, and Z_q is the surface area. The importance weight of a spot is

\tilde w = \frac{\tilde p(\boldsymbol{x})}{\tilde q(\boldsymbol{x})} = \text{depth at that spot}.

The data. A teaching example with four random surface spots (invented numbers):

Spot Depth \tilde w (m) Plankton \phi (cells per mL)
1 1 30
2 2 25
3 8 10
4 1 35

The naive answer treats each surface spot as equal, as if every spot held the same amount of water:

\frac{30 + 25 + 10 + 35}{4} = 25.

The importance-sampling answer weights each spot by its depth, because spot 3 sits over eight times as much water as spot 1:

\hat\Phi = \frac{1(30) + 2(25) + 8(10) + 1(35)}{1 + 2 + 8 + 1} = \frac{195}{12} = 16.25.

The deep, low-plankton water pulls the estimate down. The naive average overstated the concentration because the surface method over-represents the shallows relative to how much water they hold.

The side product. The average weight is 12/4 = 3 m. It estimates Z_p/Z_q, the lake’s volume divided by its surface area, which is the average depth. Multiplying by the known surface area estimates the volume, which no one ever measured directly.

How the two methods compare. Both produce a weighted average of \phi. Regular Monte Carlo needs samples from p and gives each weight 1. Importance sampling uses samples from a proposal we can draw from and gives each a weight \tilde p/\tilde q that corrects for where it came from. The weighted estimate is not exactly unbiased for a fixed R, though it converges to the right answer as R grows.

Where it goes wrong. If the lake has a narrow canyon that no random surface spot happens to land on, the canyon’s water never enters the sum and the estimate is off, with nothing in the four readings to warn us. When a spot does land on the canyon, its huge depth dominates the weights. This is the failure described above, where a proposal rarely visits where p has mass and a few samples with huge weights dominate the sum.

Rejection sampling

Importance sampling estimates expectations but never produces samples from p. Rejection sampling is a tool for Problem 1: it produces exact samples from p. The lecture presents it for a complicated one-dimensional density p(x)=\tilde p(x)/Z_p, with the same kind of proposal as before, \tilde q(x) = Z_q\,q(x), that we can sample from and evaluate. One more assumption: we know a constant c with

c\,\tilde q(x) \ge \tilde p(x) \quad\text{for all } x,

so the scaled proposal c\tilde q is an envelope lying everywhere on or above \tilde p.

Rejection sampling

  1. Generate two random numbers:
    1. x from the proposal density q(x);
    2. u uniformly from the interval [0,\ c\,\tilde q(x)].
  2. Compare u with \tilde p(x):
    1. if u>\tilde p(x), reject x;
    2. otherwise accept x: add it to the set of samples \{x^{(r)}\} and discard u.
  3. Repeat until enough samples are accepted.

Figure 6. Rejection sampling. Given x drawn from q, the point (x,u) is uniform on the vertical segment under the dashed envelope c\tilde q(x). It is accepted when it falls in the shaded region under \tilde p(x).

Geometrically, the pair (x,u) is a point drawn uniformly from the area under the envelope c\tilde q. Keeping only the points under \tilde p leaves points uniform under \tilde p, and the x-coordinate of a point uniform under a curve is distributed in proportion to that curve’s height, which is exactly p.

Why it works. The lecture flags this proof as advanced. We want to show that for any set A, an accepted x lands in A with probability \mathbb{P}_{x\sim p}(x\in A) = \mathbb{E}_{x\sim p}[\mathbf{1}_{\{x\in A\}}]. Given x, u is uniform on [0,c\tilde q(x)], and \tilde p(x)\le c\tilde q(x), so

\mathbb{P}\big(u\le\tilde p(x)\mid x\big) = \frac{\tilde p(x)}{c\,\tilde q(x)}.

Write “accept” for the event u\le\tilde p(x). By the definition of conditional probability,

\mathbb{P}_{q}(x\in A\mid \text{accept}) = \frac{\mathbb{P}_{q}(x\in A,\ \text{accept})}{\mathbb{P}_{q}(\text{accept})},

where the subscript q means x is drawn from q.

Averaging the acceptance probability above over x\sim q writes the numerator and denominator as expectations:

\mathbb{P}_{x\sim q}\big(x\in A,\ u\le\tilde p(x)\big) = \mathbb{E}_{x\sim q}\Big[\mathbf{1}_{\{x\in A\}}\,\frac{\tilde p(x)}{c\,\tilde q(x)}\Big], \mathbb{P}_{x\sim q}\big(u\le\tilde p(x)\big) = \mathbb{E}_{x\sim q}\Big[\frac{\tilde p(x)}{c\,\tilde q(x)}\Big].

Each expectation is an integral against q(x) = \tilde q(x)/Z_q, so \tilde q cancels inside it. The denominator becomes \frac{1}{cZ_q}\int\tilde p(x)\,dx = \frac{Z_p}{cZ_q}, and the numerator becomes \frac{1}{cZ_q}\int_A\tilde p(x)\,dx = \frac{Z_p}{cZ_q}\,\mathbb{P}_{x\sim p}(x\in A). Dividing,

\mathbb{P}_{x\sim q}\big(x\in A\mid u\le\tilde p(x)\big) = \mathbb{P}_{x\sim p}(x\in A).

So accepted samples are distributed exactly according to p, and Z_p never had to be known.

Rejection sampling in many dimensions. The denominator above is the probability that a proposal is accepted:

\text{acceptance rate} = \frac{\text{area under }\tilde p}{\text{area under }c\tilde q} = \frac{Z_p}{cZ_q}.

In high-dimensional problems, the requirement c\tilde q(x)\ge\tilde p(x) everywhere forces c to be huge, so acceptances become very rare. In general c grows exponentially with the dimension, so the acceptance rate is expected to be exponentially small in the dimension. Finding a valid c at all is also hard, since we do not know where the modes of \tilde p are or how high they are. This is why the lecture presents rejection sampling as a one-dimensional tool.

TipRecap: Rejection sampling

What the symbols stand for:

  • c: a constant large enough that c\,\tilde q(x) \ge \tilde p(x) everywhere. Then c\,\tilde q is the envelope.
  • u: a uniform random height between 0 and the envelope at the proposed x.
  • “Accept”: the event u \le \tilde p(x), the point lands under the target curve.
  • A: any set of x values, used in the proof.

Taking the equations apart:

  • \mathbb{P}(\text{accept} \mid x) = \tilde p(x) / (c\,\tilde q(x)): the fraction of the vertical segment at x that lies under \tilde p.
  • The proof shows accepted x values land in any set A with probability \mathbb{P}_p(x \in A), so accepted samples come exactly from p.
  • Acceptance rate = Z_p / (c Z_q): area under the target divided by area under the envelope.

A teaching example. Let \tilde p(x) = x on [0, 1] (so p(x) = 2x and Z_p = 1/2). Take q uniform on [0, 1] with \tilde q = 1 and c = 1; the envelope is the flat line at height 1, which sits above \tilde p.

  • Propose x = 0.8, draw u = 0.6: since 0.6 \le 0.8, accept.
  • Propose x = 0.3, draw u = 0.5: since 0.5 > 0.3, reject.
  • Acceptance rate = (1/2)/(1 \cdot 1) = 0.5.

Now do the same in D dimensions with \tilde p(\boldsymbol{x}) = x_1 x_2 \cdots x_D on the unit cube. The acceptance rate becomes (1/2)^D, about 0.001 at D = 10: the exponential collapse described above.

Comparing the sampling methods

TipQuestion: What do the hat, the tilde and the word proposal mean?

Three pieces of notation come up in every method in this section.

  • The hat on \hat\Phi. A hat marks an estimate computed from samples. \Phi is the true expectation, and \hat\Phi is what the sample average or weighted average gives us. The hat is not a property of the density.
  • The tilde on \tilde p. A tilde marks an unnormalized density: a formula we can evaluate, but which does not integrate to 1. The true density is p = \tilde p / Z_p, where Z_p is the constant that makes it integrate to 1. The tilde version has the same shape as p, just scaled. The tilde goes on \tilde p, \tilde q and \tilde w, but not on p itself, which is already normalized.
  • The proposal q. A proposal is a distribution we choose and can sample from, and use in place of p when we cannot sample p directly. It is written with the same tilde convention: \tilde q is its unnormalized form, with q = \tilde q / Z_q. A good proposal covers p (so q > 0 wherever p > 0) and has roughly the same shape. Importance sampling draws from q and reweights. Rejection sampling draws from q and accepts or rejects using an envelope c\tilde q.

What the tilde tells you. A tilde means the formula is known but its normalizing constant may not be. \tilde p and \tilde q are what we can evaluate. p and q are normalized, so they integrate to 1 and give real probabilities. The same split applies to the weights:

  • \tilde w_r = \tilde p(x^{(r)})/\tilde q(x^{(r)}) is what we compute. It is not normalized. Its average over draws estimates Z_p/Z_q, so it is not a probability.
  • w_r = \tilde w_r / \sum_{r'}\tilde w_{r'} is normalized. The w_r sum to 1, and the estimator \sum_r w_r\,\phi(x^{(r)}) uses them.

When to use which.

  • Use the tilde when the constant is unknown or cancels: in algorithms, such as the rejection test u \le \tilde p(x) and the envelope c\tilde q \ge \tilde p, where Z_p and Z_q never need to be computed.
  • Use the plain form when the constant matters: stating the target \Phi = \mathbb{E}_p[\phi], quoting the acceptance rate Z_p/(cZ_q), or reporting a probability.
  • Do not compare a tilde value with a plain one. A value \tilde p(x) = 3 says nothing about p(x) by itself. Only ratios carry over: \tilde p(x)/\tilde p(y) = p(x)/p(y).

The four methods in this half of the lecture are easy to blur together, so it helps to sort them by two questions. Which problem does the method solve: drawing samples (Problem 1) or estimating an expectation (Problem 2)? And what does it need from us before it can run?

Method Solves Needs Produces Struggles when
Ancestral sampling (Ancestral sampling) Problem 1 a DAG whose conditionals we can sample, in topological order exact, independent samples from p we condition on observed descendants, or the model is not a DAG of normalized conditionals
Simple Monte Carlo (Simple Monte Carlo) Problem 2 samples from p itself an unbiased estimate of \Phi with variance \mathrm{var}[\phi]/R we have no way to sample p
Importance sampling (Importance sampling) Problem 2 \tilde p to evaluate; a proposal q to sample and evaluate a weighted estimate of \Phi, plus an estimate of Z_p/Z_q; no samples from p q rarely visits where p has mass, so a few large weights dominate
Rejection sampling (Rejection sampling) Problem 1 \tilde p to evaluate; a proposal q; a constant c with c\tilde q \ge \tilde p everywhere exact samples from p the dimension grows, since the acceptance rate Z_p/(cZ_q) shrinks exponentially

Read as a decision: if we can sample p directly (ancestral sampling is one way), use simple Monte Carlo on those samples. If we can only evaluate \tilde p, choose importance sampling when an expectation is all we need, and rejection sampling when we need the samples themselves and the problem is low-dimensional. The three examples below use invented numbers, one for each branch.

TipExample 1: When to use ancestral sampling with simple Monte Carlo

In plain terms: when the model is a chain of “this causes that” steps and each step is a probability table we can roll against, we can generate exact samples cheaply. Then we just count.

Take a three-node chain x_1 \to x_2 \to x_3 of binary variables with p(x_1{=}1) = 0.3, p(x_2{=}1 \mid x_1{=}1) = 0.9, p(x_2{=}1 \mid x_1{=}0) = 0.2, p(x_3{=}1 \mid x_2{=}1) = 0.8, and p(x_3{=}1 \mid x_2{=}0) = 0.1. We want \mathbb{P}(x_3{=}1), which is \mathbb{E}_p[\phi] for the indicator \phi(x) = \mathbf{1}_{\{x_3=1\}}.

  • Ancestral sampling draws x_1, then x_2 given x_1, then x_3 given x_2. Suppose five samples come out with x_3 = 1, 0, 0, 1, 0.
  • Simple Monte Carlo averages the indicator: \hat\Phi = 2/5 = 0.4.
  • The exact answer, for checking, is \mathbb{P}(x_2{=}1) = 0.3(0.9) + 0.7(0.2) = 0.41, so \mathbb{P}(x_3{=}1) = 0.41(0.8) + 0.59(0.1) = 0.387.

Why not the others: nothing here is unnormalized, so there is no Z_p to dodge. Importance sampling would only add weights that correct for a mismatch we do not have, and rejection sampling would throw away draws that ancestral sampling keeps. If we instead observed x_3 and wanted p(x_1 \mid x_3), ancestral sampling would no longer apply directly, because it only samples forward from parents to children.

TipExample 2: When to use importance sampling

In plain terms: when we can score how plausible each value is but cannot draw from that distribution, and all we want is an average, we can draw from something easy and reweight. Every draw gets used.

A coin has unknown bias \theta, with a uniform prior on [0, 1]. We see two heads and one tail. The posterior is known only up to a constant: \tilde p(\theta) = \theta^2(1-\theta). We want the posterior mean \mathbb{E}_p[\theta].

Use the prior as the proposal, q(\theta) = 1 on [0, 1], with \tilde q = 1. Then the weight \tilde p / \tilde q is just the likelihood of the data at each draw. Four draws from q:

\theta^{(r)} 0.2 0.5 0.7 0.9
\tilde w_r = \theta^2(1-\theta) 0.032 0.125 0.147 0.081

\hat\Phi = \frac{0.2(0.032) + 0.5(0.125) + 0.7(0.147) + 0.9(0.081)}{0.032 + 0.125 + 0.147 + 0.081} = \frac{0.2447}{0.385} \approx 0.64.

The exact posterior mean is \int_0^1 \theta^3(1-\theta)\,d\theta \,\big/ \int_0^1 \theta^2(1-\theta)\,d\theta = \frac{1/20}{1/12} = 0.6. The average weight 0.385/4 \approx 0.096 also estimates Z_p/Z_q = Z_p = 1/12 \approx 0.083, the probability of the observed data.

Why not the others: we cannot sample the posterior directly, so simple Monte Carlo on its own is out, and ancestral sampling does not condition on observed data. Rejection sampling would work in one dimension, but it discards some draws and needs a bound c. Since we only want an average, importance sampling uses every draw and gives Z_p for free.

TipExample 3: When to use rejection sampling

In plain terms: when we need actual values drawn from the distribution (to plot them, or to feed them into another simulation), and the problem is low-dimensional with a known ceiling on \tilde p, we can propose values and keep only the ones that pass a fair test.

Keep the coin posterior \tilde p(\theta) = \theta^2(1-\theta) from Example 2, but now suppose we want a set of exact posterior draws of \theta, for instance to simulate the next ten flips under each draw. Importance sampling cannot give us that, because its draws come from q and only the weights carry p.

The peak of \tilde p is at \theta = 2/3, where \tilde p = 4/27 \approx 0.148. With the uniform proposal \tilde q = 1, the constant c = 4/27 gives an envelope at least as high as \tilde p everywhere. Draw \theta from q, then u uniformly from [0, 4/27]:

  • \theta = 0.7, u = 0.10: \tilde p(0.7) = 0.147 and 0.10 \le 0.147, so accept.
  • \theta = 0.2, u = 0.05: \tilde p(0.2) = 0.032 and 0.05 > 0.032, so reject.

The acceptance rate is Z_p/(cZ_q) = (1/12)/(4/27) = 0.5625, so a bit over half of the proposals become exact posterior samples.

Why not the others, and where this breaks: ancestral sampling and simple Monte Carlo again need samples from p that we do not have. The catch is dimension. With twenty independent coins of this kind and the matching product envelope, the acceptance rate becomes 0.5625^{20} \approx 10^{-5}, about one acceptance per hundred thousand proposals. At that point rejection sampling is no longer practical, and we need methods that do not rely on a global envelope.

Summary

Note

Key takeaways from Week 4:

  • Latent variables and TrueSkill. TrueSkill models each player’s skill as a latent variable with p(i\text{ beats }j\mid z_i,z_j)=\sigma(z_i-z_j). Observing games couples the skills (explaining away), so the exact posterior needs a high-dimensional integral.
  • Message passing on trees. On a tree, eliminating from the leaves inward is optimal, and the intermediate factors become messages m_{j\to i}(x_i)=\sum_{x_j}\psi_j\psi_{ij}\prod_{k\ne i}m_{k\to j}. A node’s normalized belief b(x_i)\propto\psi_i\prod_j m_{j\to i} is its exact marginal.
  • Belief propagation. Two passes (leaves to root, root to leaves) compute every marginal on a tree. On graphs with cycles, loopy BP iterates the same updates from uniform messages; it gives approximate, often over-confident beliefs, may not converge, and is stabilized by normalization and momentum. Replacing the sum with a max gives max-product BP, whose max-marginals yield the MAP estimate.
  • Image denoising. A noisy binary image’s posterior is an Ising MRF with edge potentials e^{Jx_sx_t} and node potentials e^{\beta y_sx_s}, \beta=\tfrac12\log\frac{1-\epsilon}{\epsilon}, and loopy BP approximates its pixel marginals.
  • Monte Carlo. Ancestral sampling draws from a DAG in topological order. Simple Monte Carlo estimates \mathbb{E}_p[\phi] by a sample average that is unbiased with variance \mathrm{var}[\phi]/R, independent of dimension. When p is known only up to Z, importance sampling reweights samples from a proposal q by \tilde p/\tilde q, and rejection sampling accepts proposals that fall under \tilde p beneath an envelope c\tilde q, at an acceptance rate Z_p/(cZ_q) that collapses in high dimensions.

High-level overview

This section retells each part of the week in plain language and without formulas, using the lecture’s own examples. Read it before the chapter for orientation, or after it as a review.

Latent variables and TrueSkill (Latent variables and the TrueSkill model). Some quantities matter but are never observed. In TrueSkill, each player has a hidden skill, and all we see is who beat whom. The stronger player is more likely to win, but upsets happen. One game links the two players’ skills: if A beat B, then A is strong, or B is weak, or both. With many players and games, finding everyone’s skill exactly requires a huge integral, which motivates the rest of the week.

Trees and elimination order (Trees and elimination order). On a tree (a graph with no loops), variable elimination is easy: always remove a leaf first. Removing a leaf touches only its one neighbour, so no large intermediate table ever appears.

Worked example: elimination becomes message passing (Worked example: elimination on a tree becomes message passing). On a five-node tree, eliminating from the leaves inward means each step produces a small summary that one node hands to its neighbour. These summaries are the messages.

Messages and beliefs (Messages and beliefs). A message from node j to node i is j’s summary of everything on its side of the tree, phrased as “how well each value of i fits with what I know”. A node’s belief combines its own local evidence with every message it receives. On a tree, that belief is exactly the correct probability for the node.

Belief propagation on trees (Belief propagation on trees). To get every node’s probabilities, not just one node’s, send messages inward to a root and then back out again. Each message is computed once and reused, so all the answers together cost about twice as much as a single one.

Loopy belief propagation (Loopy belief propagation). A graph with loops has no leaves to start from. Loopy BP starts every message at “no opinion” and keeps updating until things settle. The answers are approximate and tend to be overconfident, because evidence travelling around a loop gets counted more than once, and sometimes the updates never settle at all.

Max-product BP and MAP inference (Max-product BP and MAP inference). Sometimes we want the single best overall explanation rather than a probability for each variable. Replacing “add up the possibilities” with “keep the best possibility” in every message gives that best explanation.

Image denoising with loopy BP (Tutorial example: image denoising with loopy BP). A black-and-white Mona Lisa passes through a channel that flips some pixels at random. Cleaning it up balances two pulls on each pixel: stay close to the colour that was received, and agree with the neighbours, since real images have large smooth regions. Loopy BP balances these pulls across the whole grid, so isolated flipped pixels get pulled back to match their surroundings.

Sampling from an unnormalized density (Sampling from an unnormalized density). The second half switches strategy: instead of computing sums, draw random examples and average over them. The catch is that we often know a distribution only up to an unknown scaling constant. We can say one point is twice as likely as another, but not the actual probability of either.

Ancestral sampling (Ancestral sampling). In a DAG, sampling is easy: sample the variables without parents first, then each child given its parents’ values, and so on down the graph. For the weather chain, first decide whether the pressure is low, then whether it rains given the pressure, then the traffic given the rain.

What sampling is for (What sampling is for). Two separate jobs. The first is to produce random examples that follow the distribution. The second is to estimate an average, such as an expected value, under it.

Simple Monte Carlo (Simple Monte Carlo). If we can draw examples, we estimate an average by averaging over them. To estimate a fair die’s average roll, roll it many times and take the mean. The estimate is right on average, and its typical error shrinks as samples are added (four times as many samples halve it), however many dimensions the problem has.

Why the normalizing constant is hard (Why the normalizing constant is hard). The lecture’s lake picture: we want the average plankton concentration in a lake, and from a boat we can measure the depth and the plankton at any spot. If a few narrow, very deep canyons hold much of the water, randomly chosen spots rarely land on them, and we badly misjudge the total. High-dimensional distributions behave like this, with most of the probability in tiny regions. Checking every point on a grid is no escape, because the number of grid points multiplies with every added dimension.

Importance sampling (Importance sampling). When we cannot sample from the distribution we care about, we sample from an easier one and correct the mismatch with weights. A point the easy distribution produces too often gets a small weight, and a point it produces too rarely gets a large one. The weighted average then estimates the average we wanted, and the unknown scaling constants cancel. It works only if the easy distribution covers the important regions. If it misses a canyon, a few huge weights dominate the answer.

Rejection sampling (Rejection sampling). Choose an easy distribution that, once scaled up, lies above the target everywhere. Propose points from it and keep each one with a chance equal to the target’s height divided by the cover’s height at that point. The points we keep are exact samples from the target. In high dimensions, though, almost every proposal is rejected.

Comparing the sampling methods (Comparing the sampling methods). Every method above depends on an easy distribution that resembles the target, and such a distribution is very hard to find in high dimensions. Week 5’s Markov chain methods avoid needing one.
