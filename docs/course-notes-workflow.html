Course-notes workflow

How the books on this site are written in Claude Code

Each course is a Quarto book under courses/<slug>/. The week chapter lectures/weekNN.qmd is the source of truth. HTML is render output. Slash commands never commit or push; that is always /commit, then (for the public site) /deploy-course-notes.

Run this in Claude Code. Use plan mode while asking questions about a week (read-only). Leave plan mode for edits, park/promote, audit, and commit.

Weekly loop

  1. Drop lecture PDFs in courses/<slug>/sources/weekN/.
  2. /course-notes add <slug> N — approve the pre-flight, then one week chapter is written and rendered.
  3. Read the chapter. /course-notes revise <slug> [N] — ask questions; promote fixes into the section or park a clarification dropdown.
  4. /course-notes audit <slug> — cold fact check of the whole course.
  5. /commit — source .qmd on git.
  6. /deploy-course-notes <slug> then /commit and push — when the public Pages book should update. Parked dropdowns ship with that HTML.
/course-notes add CSC2506 3
/course-notes revise CSC2506 3
/course-notes audit CSC2506
/commit
/deploy-course-notes CSC2506
/commit

Commands

Every command that belongs to this workflow:

/course-notes

Command What it does
/course-notes init <slug> Scaffold courses/<slug>/ from the book template. Fill COURSE.md placeholders next. Does not write week notes.
/course-notes add <slug> <N> Plan, then write one week (1 → lectures/week01.qmd), append the glossary, list the chapter in _quarto.yml, render locally.
/course-notes revise <slug> [N] Pre-audit pass on that week. Questions stay in chat. Writes only on the cues below.
/course-notes audit <slug> Fact-audit the whole course (every week chapter, glossary, index). Writes FACT_AUDIT.md. No per-week form.

Flags (on /course-notes):

  • --no-render — skip quarto render on add, and after a revise park or promote.
  • --no-audit — do not run audit after add even if you asked in the same message. Does not block saying audit during revise.

Slug is kebab-case (CSC2506, imaging-2026). Week N is an integer; the file is always zero-padded weekNN.qmd.

Cues during revise

If none of these appear, a follow-up is treated as more clarification (no write).

You say What happens
promote Edit the section in lecture voice. No dropdown.
park Collapsed Clarification dropdown at the end of that section. Ships on Pages.
discard Drop the last explanation. Stay in revise.
audit Leave revise; run /course-notes audit. Chat-only text is not on the page.
commit Leave revise. The skill does not commit; it tells you to run /commit.

Publish and ship

Command What it does
/deploy-course-notes <slug> Quality ≥ 80, quarto render, copy _site/ to docs/courses/<slug>/. Does not commit.
/deploy-course-notes all Same for every course book (all / ALL / All).
/commit Stage, quality gates, commit. Default: branch + PR + merge to main. /commit nopr skips the PR and pushes main. Used after source edits and again after deploy, then push to main.

Script equivalent of deploy: ./scripts/sync_course_notes_to_docs.sh CSC2506 (or all).

Public URL shape: https://amcwong.github.io/claude-code-my-workflow/courses/<slug>/. GitHub Pages source must be branch main, folder /docs.

Optional, nearby

  • /learn — save a generic process lesson as [LEARN:course-notes]. Course-specific repeats go in that course’s COURSE.md.
  • /deploy — instructor RevealJS slides only. Not this workflow.

Not supported

/course-notes audit CSC2506 3
/course-notes add CSC2506
/course-notes deploy CSC2506

Audit is always the whole course. add needs a week number. Publishing is /deploy-course-notes, not a course-notes subcommand.

First course

  1. /course-notes init <slug>
  2. Fill COURSE.md (audience, course URL, expected week count).
  3. Put Week 1 slides in sources/week1/.
  4. Then the weekly loop from add.
